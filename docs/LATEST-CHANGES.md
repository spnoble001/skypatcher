# Latest Changes

This document summarizes the most recent PerfectPatch architecture and UI
changes.

## Current modules

The active module set is now intentionally small:

- `PatchCrumbs`: detects crumbs and produces directional patch geometry.
- `SimpleAssist`: captures a directional patch and places from its terminal wall
  toward the crumb origin.
- `RightClicker`: generic right-click fallback when SimpleAssist does not own
  the input channel.

`FullAutoV2` and `FullAutoV3` were removed from source, module registration,
ClickGUI, debug controls and documentation.

## SimpleAssist consolidation

The previous Beta3 variants were consolidated into one public class:

```text
src/main/java/perfectpathc/dev/modules/combat/SimpleAssist.java
```

Removed implementations:

- `Beta3`
- `Beta3Simple`
- Planner/`HashSet` architecture

The selected SimpleAssist architecture contains:

```text
ActivePatch capturedPatch
BlockPos cursor
PlacementState placementState
BlockPos pendingTarget
Block pendingExpectedBlock
```

### Geometry

`PatchCrumbs` exposes fresh directional geometry:

```text
ActivePatch
  origin:   coordinate at the crumb axis
  terminal: obsidian wall reached by the scan
  box:      logical/render bounds
```

The terminal distance is dynamic (`n`), not a fixed number of blocks.

```text
North/south shot, player west:
terminal X+n → X+(n-1) → ... → origin X

North/south shot, player east:
terminal X-n → X-(n-1) → ... → origin X
```

East/west shots apply the same formula on Z. The existing terminal obsidian is
validated and skipped; the first actual placement is its adjacent cell toward
the origin.

### Trigger and placement

```text
SimpleAssist enabled
  → active crumb and current ActivePatch
  → crosshair raycast touches terminal obsidian
  → capture patch
  → walk cursor toward origin
  → validate replaceable cell, support and vanilla reach
  → direct onPlayerRightClick interaction
  → WAITING_CONFIRMATION
  → confirm expected block in the world
  → advance cursor
  → confirmed origin releases capture
  → immediate handoff to the next terminal under the crosshair
```

SimpleAssist does not rotate or move the player, change slots, or require the
physical right mouse button to remain held.

### Timing

- CPS setting: 1–20.
- Hard maximum: 20 CPS.
- Humanized interval generated by `ClickerUtils`.
- Minimum interval: 66.67 ms.
- Maximum one interaction per client tick.
- Maximum one pending confirmation.
- Ping-adaptive confirmation timeout: 3–10 ticks.
- Failed-placement backoff: 2 ticks.

## RightClicker

The generic `RightClicker` module was added with:

- CPS setting from 1 to 40.
- Optional `Blocks` filter.
- Physical right-button gate.
- `KeyBinding.onTick()` input generation.
- Synthetic right-mouse event through `ClickerUtils`.
- Short press/release pulse.
- Integration with `RightClickCoordinator`.

RightClicker remains independent from SimpleAssist and does not inspect patch
state directly.

## Coordinator event filtering

The coordinator now behaves as a priority filter:

```text
Physical right input / placement opportunity
  → SimpleAssist priority 31
      ├─ valid terminal or captured flow
      │    → reserve ownership during ClientTick START
      │    → suppress physical vanilla input
      │    → RightClicker cannot synthesize a click
      └─ no valid flow
           → release ownership
           → RightClicker priority 20 may continue
```

The early reservation closes the timing window in which RightClicker could have
generated a click before SimpleAssist acquired ownership. RightClicker does not
need any dependency on SimpleAssist.

## Commands and debug mode

Commands changed to:

- `.patch`: opens ClickGUI locally.
- `.patchdebug`: toggles the diagnostic overlay.

The debug overlay is disabled by default. The previous F8 toggle and
`.perfectpatch` command were removed.

## Configurable keybinds

`Settings` now supports a dedicated keybind row. PatchCrumbs, RightClicker and
SimpleAssist expose `Keybind` in ClickGUI and have no fixed default key.

Usage:

1. Enter `.patch` in chat.
2. Click the module's `Keybind` row.
3. Press the desired keyboard key.

Controls while listening:

- `Escape`: cancel selection.
- `Backspace` or `Delete`: clear the keybind.
- `NONE`: module currently has no assigned key.

Keybinds currently last for the running session only; persistent configuration
storage has not been implemented.

## Rendering and PatchCrumbs

Patch rendering remains separated into:

- Fresh logical `ActivePatch` geometry used for placement authorization.
- Visual patch boxes retained for 2.5 seconds for human feedback.

The logical geometry never uses the visual-history timeout. Patch scanning is
limited around the player and stops at obsidian, another solid obstruction,
unloaded chunks or the configured maximum scan distance.

## Reviewed but not yet implemented

The following improvements were analyzed but have not been applied:

- Force `stepTowardOrigin()` to move on exactly one axis defensively. Current
  ActivePatch geometry is already horizontal and monoaxial.
- Cache `EnumFacing.values()` in a static array to avoid small repeated
  allocations.
- Replace interval measurement using `System.currentTimeMillis()` with the
  monotonic `System.nanoTime()`, if real-time timing remains after a tick-based
  scheduler is introduced.
